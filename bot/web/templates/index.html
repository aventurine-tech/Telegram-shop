Telegram Shop — Admin Panel

Quick reference for the panel. Every create/edit/delete here is audit-logged, and the bot's caches are refreshed automatically after a change.

📦 Selling goods (product + stock)

A Product is a physical item: name, price, description, category, optional sale and the number of units on hand (stock).

  1. Create a Category (if needed).
  2. Create a Product — set name, price, description, category and stock.
  3. Change stock whenever goods arrive or are written off.

stock is reserved when a customer places an order and returned when the order is cancelled. A product at 0 cannot be ordered; customers who asked to be notified get a message when it goes from 0 to more.

Renaming or deleting a product keeps carts, reviews and order history consistent automatically.

🔐 Roles & permissions

A role's permissions is a bitmask: add up the values of the abilities you want. Built-in roles: USER (1), ADMIN, OWNER (all bits). You can only grant permissions you hold yourself.

BitValueGrants
USE1Basic bot access
BROADCAST2Mass messaging
SETTINGS4Maintenance mode
USERS8View / block users, referrals, orders
CATALOG16Categories, products, stock
ADMINS32Create roles, assign roles
OWNER64Owner-only operations
STATS128Statistics, logs
BALANCE256Top-up / deduct balance
PROMO512Promo-code management
ORDERS1024View orders, verify MIA payments, change order status

Example: a catalog manager who also sees stats = USE + CATALOG + STATS = 1 + 16 + 128 = 145. Prefer the bot's role menu for a click-to-toggle UI.

🧭 What each section is for

  • Users — balance, role, block status (edits take effect immediately).
  • Roles — permission bitmasks (see the table).
  • Categories / Products — the catalog, with stock per product.
  • Orders / Order Lines — customer orders (see the tip below).
  • Promo Codes — percent / fixed / balance codes, limits, expiry.
  • Operations / Referral Earnings — read-only balance history.
  • Reviews — 1–5★ product reviews.
  • Audit Logs — read-only record of every admin action.

💡 Good to know

  • Orders, order lines, operations and audit logs are read-only by design.
  • To handle an order, tick it in the Orders list (or open it) and use the Actions menu: confirm MIA payment, confirm, shipped, completed, cancel. These run through the same logic as the bot, so stock, balance refunds, referral commissions and customer notifications always stay correct. A move that is not allowed (for example shipping an order whose MIA payment is not verified) is skipped and logged. Cancelling does not return cash or MIA money — refund it by hand.
  • CSV exports: /export/users, /export/orders, /export/order_items, /export/operations (optional ?from=YYYY-MM-DD&to=YYYY-MM-DD).
  • Prices/balances use exact decimals — enter plain numbers (e.g. 199.99).
  • A promo code's discount_type is one of percent, fixed, or balance.
  • Most day-to-day tasks are also available in the bot's in-chat admin menu, which is often quicker for catalog and role edits.
